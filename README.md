# فرصة — React / TypeScript / Vite / Capacitor Android

## البناء

المتطلبات: Node.js **22.12+**، Java **21**، Android SDK **36** (minSdk 24 / Android 7+).

```sh
npm ci
npm test
npm run build
npm run cap:sync
cd android
./gradlew assembleDebug lintDebug testDebugUnitTest
```

الواجهة مضمنة داخل APK (`dist`)، وليست WebView تحمل موقعًا خارجيًا. `HashRouter` و`base: './'` يدعمان مسارات Capacitor والنشر تحت `/forsah/`. لا تضبط `server.url` على موقع الإنتاج.

API الافتراضي للواجهة ولوحة الإدارة:

```
https://t3lam.site/forsah/api.php
```

يمكن تغييره عبر `VITE_API_BASE_URL` **قبل** البناء. لا تضع أسرارًا في متغيرات Vite. العنوان يفترض نشر `backend/api.php` كـ `/forsah/api.php`، وليس `/forsah/backend/api.php`.

## GitHub Actions

الملف `.github/workflows/android.yml` يعمل عند الدفع لفرع العمل، أو يدويًا بـ `workflow_dispatch` بعد توفره في الفرع الافتراضي. مهام منفصلة:

1. اختبارات عميل API، TypeScript/build، تدقيق اعتماديات التشغيل، PHP syntax واختبار PHP/SQLite المعزول.
2. فحص الخادم المنشور للـ HTTPS وعقد الخدمات وCORS من أصل Android وحماية الإدارة. لا ينشئ بيانات إنتاج ولا يجرب كلمات مرور.
3. بعد نجاح الاختبارات المحلية: مزامنة Capacitor، بناء APK، Android lint واختبارات Java، التحقق من توقيع APK ونشر artifact باسم `forsah-debug-apk` مع SHA-256.

**فشل فحص الخادم لا يمنع إنتاج APK للاختبار، لكنه يجعل workflow غير ناجح ويعني أن النسخة ليست جاهزة للخدمة الحية.** انظر ملخص المهام، لا تكتف بوجود ملف APK.

التوقيع Debug للاختبار فقط؛ مفتاح GitHub runner مؤقت وقد يستلزم إزالة النسخة السابقة قبل تثبيت بناء جديد (ما يحذف بياناتها المحلية). إصدار توزيع ثابت يحتاج keystore خاصًا محفوظًا في GitHub Secrets وإعداد release signing؛ لا نستخدم مفتاح debug على أنه إصدار إنتاج.

## نشر الخادم على t3lam.site

1. استضافة PHP 8.1+ مع `pdo_sqlite` و`mbstring` وHTTPS صالح.
2. ارفع `backend/api.php` إلى `public_html/forsah/api.php`، ويمكن رفع محتويات `dist/` إلى نفس المجلد لواجهة الويب.
3. اضبط `FORSAH_DB_PATH` على مسار مطلق **خارج public_html** قابل للكتابة بواسطة PHP؛ لا تضع قاعدة SQLite أو نسخها الاحتياطية في مسار عام. لا تعتمد المسار الافتراضي بعد نسخ API إلى مكان آخر.
4. اضبط `FORSAH_CORS_ORIGINS=https://t3lam.site,https://localhost`. القيمة الثانية هي **أصل WebView المحلي** وليست عنوان الخادم. لا تستخدم `*` في الإنتاج. مرر Authorization إلى PHP إذا كان خادم الويب يحذفه.
5. أنشئ المدير عبر CLI باستخدام `backend/bootstrap-admin.php` مع **نفس** `FORSAH_DB_PATH`، خارج مجلد الويب. لا ترفع أداة bootstrap أو الاختبارات أو ZIP أو الأسرار إلى الموقع.
6. شغّل `npm run check:server` من بيئة يمكنها الوصول للموقع.
7. اختبر إرسال إعلان/دعم بحسابات وبيانات مخصصة للاختبار، وتأكد من وصولها إلى الإدارة `https://t3lam.site/forsah/#/admin`، ثم احذف بيانات الاختبار.

لا ينشر workflow ملفات إلى الاستضافة؛ إعداد استضافة PHP منفصل ويتطلب وصولًا إلى الخادم.

## ما يعمل وما لم يُنفذ

- المظهر والتنقل وتصنيفات الخدمات والبحث **في التصنيفات المحلية**.
- إرسال إعلان إلى الخادم بحالة انتظار المراجعة؛ لا نجاح وهمي عند انقطاع الشبكة.
- إرسال تذاكر الدعم؛ إدارة التذاكر والردود في لوحة الإدارة.
- دخول الإدارة وصلاحياتها وإدارة الإعلانات والمستخدمين والبلاغات والتذاكر، حسب API الموجود واختباراته.
- زر رجوع Android، منع HTTP الصريح، حفظ إعدادات الواجهة.

**غير مكتمل في المشروع الأصلي وغير مضمون في هذا البناء:** تسجيل ودخول المستخدم العام، قائمة إعلاناته ومتابعتها، عرض سوق إعلانات عامة وبيانات مقدمي خدمات حقيقية، المفضلة وسجل البحث، المحادثات المباشرة وقراءة المستخدم ردود الدعم، رفع الصور، إشعارات الدفع، البصمة، الإنجليزية، واجهة الإبلاغ العامة. عطّلنا مفاتيح الإشعارات والبصمة ودخول المستخدم بدل الإيحاء بأنها تعمل. إرسال رد دعم في الإدارة لا يرسل بريدًا تلقائيًا.

الاختبارات لا تُثبت تشغيل جميع ميزات المنتج، ولا تغني عن اختبار APK على جهاز Android حقيقي (الشبكة، لوحة المفاتيح، الرجوع، المناطق الآمنة وإعادة الفتح). تفاصيل API في [backend/README.md](backend/README.md).

## تطوير محلي

```sh
npm ci
npm run dev
```

الخادم الافتراضي إنتاج؛ للتطوير استخدم API تجريبيًا معزولًا واضبط CORS له. PHP غير مضمن في APK. لا ترسل بيانات اختبار إلى الإنتاج دون قصد.
