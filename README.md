# فرصة — إصدار السوق والحسابات 2

React + TypeScript + Vite، خادم PHP/SQLite، وتطبيق Android عبر Capacitor.
API: `https://t3lam.site/forsah/api.php`؛ ملفات الواجهة مضمنة في APK وليست تحميلًا لموقع خارجي.

## الميزات المنفذة

- التسجيل والدخول والخروج، تعديل الملف الشخصي وتغيير كلمة المرور مع إبطال الجلسات.
- إنشاء إعلانات مرتبطة بالحساب، تعديلها وحذفها، ومتابعة حالة المراجعة.
- سوق عام للإعلانات المعتمدة فقط، بحث وتصنيفات وصفحات نتائج، دون بيانات تجريبية.
- رفع 4 صور لكل إعلان (JPEG/PNG/WebP حتى 2MB)، إعادة ترميزها في الخادم لإزالة البيانات الوصفية، وحماية صور الإعلانات غير المنشورة. مشاهدة الصور في نافذة تعديل الإعلان بالإدارة قبل الاعتماد.
- مفضلة محفوظة لكل حساب وسجل بحث محلي قابل للمسح.
- محادثات بين صاحب الإعلان والمشتري، مع تحديث كل 3 ثوانٍ أثناء فتح المحادثة ومنع الوصول لغير المشاركين.
- تذاكر دعم مرتبطة بالحساب، قراءة ردود الإدارة وإرسال المتابعة وإعادة فتح التذكرة.
- نموذج بلاغات يصل إلى لوحة الإدارة بهوية المُرسل المستمدة من جلسته.
- العربية والإنجليزية في الواجهة العامة، RTL/LTR، المظهر والنمط، ومسح التخزين المؤقت.
- فتح جلسة مشفرة عبر Android Keystore وBiometricPrompt على جهاز يدعم strong biometrics. لا تحفظ كلمة المرور. تقفل جلسة العضو عند انتقال التطبيق للخلفية إذا تم تفعيل البصمة.
- لوحة الإدارة الحالية وصلاحياتها وتدقيق العمليات وحظر المستخدمين.

**إشعارات الدفع مستبعدة بطلب المستخدم.** لا توجد خدمة بريد للتحقق من العناوين أو استعادة كلمة المرور، ولا مدفوعات أو حجز خدمات. لوحة الإدارة بالعربية. لا تعني عبارة «منفذة» أنها اختُبرت على خادم الإنتاج أو جهاز فعلي؛ راجع الاختبارات وخطوات القبول أدناه.

## التشغيل والبناء

Node 22.12+، Java 21، Android SDK 36؛ minSdk 24 (Android 7+ مع WebView حديث).

```sh
npm ci
npm test
npm run build
npm run cap:sync
cd android
./gradlew assembleDebug lintDebug testDebugUnitTest
```

PHP 8.1+ مع `pdo_sqlite`, `mbstring`, `gd`:

```sh
php -l backend/api.php
php -l backend/market.php
python3 backend/tests/smoke.py
python3 backend/tests/market.py
```

الاختبارات تستخدم قاعدة معزولة مؤقتة وخادم PHP حقيقيًا. تغطي المصادقة والعزل والصلاحيات والإعلانات والصور والمفضلة والمحادثات والدعم والبلاغات والحظر. اختبارات React تستخدم API مُحاكى لاختبار العرض ومعالجة الأخطاء؛ ليست دليلًا على اتصال الإنتاج.

للتطوير: اضبط `VITE_API_BASE_URL` على API تجريبيًا منفصلًا قبل `npm run dev`. لا تستخدم الإنتاج لاختبارات الكتابة. لا تخزن أي سر في متغيرات Vite.

## الرفع اليدوي للخادم

**يجب رفع خادم v2 قبل استعمال ميزات APK الجديدة.** بناء APK لا يحدّث PHP في الاستضافة.

```sh
npm run build
python3 scripts/package-hosting.py
```

ينتج `artifacts/forsah-hosting-ready.zip` بملفات الخادم والواجهة مباشرة. فك محتوياته داخل `public_html/forsah`. التعليمات الحالية في [deployment/INSTALL.txt](deployment/INSTALL.txt). قاعدة التشغيل داخل `database/forsah.sqlite` ومحمية بملفي `.htaccess`.

بعد الرفع، `npm run check:server` يفحص health v2 وGD وHTTPS وعقد الخدمات وCORS وحماية الإدارة دون تغيير بيانات الإنتاج.

## GitHub Actions وAPK

`.github/workflows/android.yml` يختبر الواجهة والخادم أولًا ثم يبني Android ويشغّل Lint واختبارات Java ويتحقق من توقيع APK، ويرفع:

- `forsah-debug-apk`: APK + SHA256.
- حزمة الاستضافة الوحيدة `forsah-hosting-ready` تُنشر بواسطة `hosting.yml`، وليست جزءًا من تنزيل APK.
- `android-test-reports`: تقارير Android.

مهمة فحص الخادم منفصلة: قد تفشل حتى ترفع إصدار PHP الجديد. **وجود artifact لا يعني جاهزية الإنتاج.** اقرأ نتيجة كل مهمة. APK بتوقيع Debug للاختبار وليس إصدار متجر. يلزم مفتاح Release ثابت قبل التوزيع؛ مفتاح CI المؤقت قد يستلزم إزالة النسخة السابقة عند التثبيت.

## القبول اليدوي المطلوب

لم تُجرَ اختبارات على جهاز فعلي تلقائيًا. تحقق خصوصًا من البصمة (نجاح/إلغاء/تغير البصمات/خلفية التطبيق)، اختيار الصور، زر الرجوع، لوحة المفاتيح، وفقد الشبكة. تعليمات سيناريو الحسابين ومراجعة الإعلان وقراءة الدعم في دليل النشر.

ملاحظات أمنية: الجلسات opaque ومخزنة كـ hashes في الخادم، صلاحيتها 30 يومًا للعضو و12 ساعة للإدارة. منع IDOR يتم في الخادم. ربط السجلات القديمة التي لم تملك `user_id` بحساب جديد تلقائيًا **غير مسموح** حتى لا يستولي شخص على بيانات ضيف بادعاء بريده. لا توجد بيانات دخول افتراضية.

## حزمة فك الضغط مباشرةً داخل مجلد الاستضافة

```sh
npm run build
python3 scripts/package-hosting.py
```

`artifacts/forsah-hosting-ready.zip` يحتوي `index.html` و`assets/` وملفات PHP و`.htaccess` في الجذر. حسب الطلب الأخير، تُنشأ قاعدة التشغيل داخل `forsah/database/forsah.sqlite` من seed فارغة مرفقة، دون استبدال قاعدة موجودة عند التحديث. ملفا `.htaccess` يحظران المجلد والملفات المساعدة؛ يرفض API فتح القاعدة المحلية دون علامة الحماية من خادم الويب. الحزمة تتطلب Apache/LiteSpeed مع التعليمات المرفقة. عند نقل النسخة الخارجية السابقة، اتبع `INSTALL.txt` ولا تنس WAL. تعليمات الحزمة العامة السابقة التي تستخدم قاعدة خارجية لا تنطبق على هذه الحزمة المحلية الجديدة.

الاختبارات: `backend/tests/hosting.py` للقاعدة والتسجيل والحفاظ على البيانات، و`backend/tests/hosting_apache.py` لاختبار HTTP 403 فعليًا باستخدام Apache. workflow المستقل: `hosting.yml`.

### الحفاظ على التصميم ومسارات الملفات

تمت استعادة عناصر الهوية الأصلية (الخط العربي، الألوان، رأس الصفحة، بطاقات الخدمات وشريط التنقل) مع إبقاء خدمات الحسابات والإعلانات والمحادثات الفعلية. الخط مضمن محليًا بترخيصه في `public/licenses`.

بعد `vite build` يفحص `scripts/check-assets.mjs` روابط الإنتاج ويحوّل روابط HTML إلى `assets/...` دون `./` أو `/` بادئة. تبقى استيرادات JavaScript الداخلية كما أنشأها Vite لأن حذف `./` منها يكسر دلالتها. الاختبارات تغطي الجذر ومجلدًا فرعيًا ومجلدًا متداخلًا، وChromium في workflow يتحقق من تحميل الملفات وعدم وجود overflow أو أخطاء تشغيل، باستخدام API محاكى. افتح مسار المجلد مع `/` نهائية، واستخدم `#/...` للتنقل. يبقى عنوان API الإنتاجي ثابتًا.

تنزيل `forsah-hosting-ready` من GitHub يحتوي أحدث ملفات الخادم والواجهة مباشرة، دون ZIP متداخل أو حزم بديلة. لم نعد ننشر `forsah-ui-update` أو `forsah-hosting-fix`.

### استعادة بنية التصميم الأصلي (وليس تقليد الألوان)

- `src/index.css` مستعاد من ZIP الأصلي (عدا تحميل الخط المحلي بدل Google Fonts).
- `OriginalViews.tsx` يحتفظ ببنية الرئيسية الأصلية، بطاقات الخدمات وشرائحها، الاختصارات، وصفوف الإعدادات. تنسيقات الميزات المستحدثة فقط في `market.css`؛ لا توجد قواعد عامة تعيد رسم الرئيسية.
- الجرس والرسائل في الرأس يفتحان popover لا يغير عنوان الصفحة أو تمريرها. تغلق القوائم بالتبديل، Escape، الضغط خارجها أو الانتقال الصريح من عنصر داخلها.
- الجرس يعرض تحديثات الحساب من endpoints الحالية للإعلانات والمحادثات والدعم؛ علامات المراجعة محفوظة على هذا الجهاز وليست ادعاءً بخدمة إشعارات دفع. يمكن اختيار الفئات من الإعدادات. لا يحتاج هذا التحديث تغيير الخادم.
- إنشاء الإعلان وتسجيل الدخول نوافذ فوق الواجهة، مع حصر التركيز وإرجاعه عند الإغلاق؛ بقية الميزات الفعلية ما زالت متاحة.
- اختبار Chromium يبني نسخة مرجعية مباشرة من ZIP في مجلد artifacts (لا تُنشر) ويقارن هندسة الرأس والبطاقة الرئيسية وشبكة الخدمات والبطاقات والاختصارات والتنقل عند عروض 360 و390 و768 و1280 بكسل. تُرفق صور المقارنة وتقاريرها في artifact `browser-review`.

## تحديث الجلسات والصور والإدارة الأولى
- حفظ جلسة Android مشفرة بـ Keystore واستعادتها بعد إعادة تشغيل التطبيق؛ في الويب حفظ الرمز محليًا (لا تُحفظ كلمة المرور). انتهاء الجلسة أو إلغاؤها يتطلب الدخول مجددًا، لكن فشل الشبكة وحده لا يمحوها.
- قاعدة جديدة داخل مجلد الخادم عند عدم وجودها، وأول حساب يصبح super_admin داخل معاملة مقفلة لمنع تعيين مديرين متزامنين. سجّل حساب المالك قبل إتاحة التثبيت للجمهور؛ لا تُرقّى حسابات قواعد موجودة تلقائيًا.
- أربع صور، ضغط JPEG محلي حتى 1920px و2MB، مصغرات مستقلة حتى 400px، ومعرض تفاصيل بأزرار وسحب ولمسات للمصغرات. الصور القديمة تُنشأ لها مصغرات عند أول طلب، مع نفس حماية الوصول.
- يتطلب هذا التحديث ZIP الاستضافة الكامل وAPK الجديد معًا. لا تُستبدل قاعدة المستخدمين الحالية.

## بداية جديدة مع الاحتفاظ بالملفات السابقة
حسب اختيار المالك، غياب `database/forsah.sqlite` يبدأ قاعدة فارغة حتى مع وجود ملفات SQLite أو إعداد قديمة خارج المجلد. لا تُحمّل هذه الملفات تلقائيًا ولا تُحذف أو تُعدّل. لا يُستورد أي حساب قديم، وأول تسجيل جديد يصبح مديرًا. سجّل حساب المالك قبل مشاركة الرابط. إعادة رفع الحزمة لاحقًا لا تعيد تهيئة قاعدة التشغيل الموجودة. الإعدادات الصريحة `FORSAH_DB_PATH`/`FORSAH_CONFIG_PATH` تبقى محترمة؛ أزلها إذا أردت التهيئة المحلية الافتراضية.
