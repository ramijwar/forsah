فرصة — حزمة فك الضغط المباشر على Apache/LiteSpeed
================================================

1) قبل أي تحديث: خذ نسخة احتياطية من الموقع وقاعدة البيانات الحالية.
2) ارفع الملف المضغوط إلى مجلد الموقع المقصود، مثل public_html/forsah.
3) فك الضغط داخل هذا المجلد مباشرة. لا توجد مجلدات public أو dist إضافية.
   تأكد من وجود index.html وapi.php و.htaccess بجوار بعض.
4) احذف ملف ZIP من الاستضافة بعد فكّه.
5) افتح https://t3lam.site/forsah/
   وفحص الخادم https://t3lam.site/forsah/api.php?resource=health
   المطلوب: ok=true وversion=2 وimages_supported=true.

المتطلبات:
- Apache 2.4 أو LiteSpeed مع دعم .htaccess وmod_rewrite والسماح بتعليماته.
- PHP 8.1 أو أحدث، وامتدادات pdo_sqlite وmbstring وgd.
- upload_max_filesize لا يقل عن 3M، post_max_size لا يقل عن 4M.
- PHP يستطيع إنشاء/كتابة مجلد خاص خارج المجلد العام (عادة مجلد الحساب).
- HTTPS صالح. .htaccess لا يُثبّت PHP أو الامتدادات ولا يُستخدم بواسطة Nginx.

قاعدة البيانات المرفقة:
- database/forsah.seed.sqlite: قاعدة حقيقية فارغة بجميع الجداول؛ لا تحتوي
  مستخدمين أو إعلانات تجريبية أو كلمات مرور. لا تُكتب فيها بيانات التشغيل.
- عند أول طلب API، ينشأ المجلد forsah-private بجوار public_html تلقائيًا،
  وتُنسخ القاعدة إلى forsah-private/forsah.sqlite بصلاحيات خاصة.
- المجلد database ممنوع عبر .htaccess؛ قاعدة التشغيل لا توجد في المجلد العام
  حتى لو تجاهل خادم الويب ملف .htaccess.
- قاعدة خاصة موجودة لا تُستبدل عند إعادة فك الضغط أو أول تشغيل.
- هذه الحزمة تستخدم مجلدًا خاصًا واحدًا باسم forsah-private لكل حساب استضافة.
  عند وجود عدة مواقع فرصة على الحساب نفسه حدّد FORSAH_DB_PATH لكل موقع.

إذا كان لديك بيانات سابقة:
- لو كانت القاعدة الحالية في forsah-private/forsah.sqlite فستُستخدم كما هي.
- الإعداد السابق forsah-private/config.php أو FORSAH_DB_PATH له الأولوية.
- لو ظهرت رسالة اكتشاف قاعدة قديمة، توقف وحدد مسارها/انقلها بأمان بدل
  إنشاء قاعدة جديدة. لا تستبدلها بقاعدة seed الفارغة ولا تنس ملفات WAL.
- ملف إعداد خاص اختياري خارج public_html:
  /home/ACCOUNT/forsah-private/config.php
  محتواه:
  <?php
  return [
    'FORSAH_DB_PATH' => '/home/ACCOUNT/forsah-private/forsah.sqlite',
    'FORSAH_CORS_ORIGINS' => 'https://t3lam.site,https://localhost',
  ];
- لا تضع الإعداد الخاص أو بيانات المستخدمين أو نسخة القاعدة الاحتياطية
  في مجلد يمكن تنزيله من الويب.

حساب الإدارة:
- لا توجد كلمة مرور مدير افتراضية، ولا يتم تحويل أول مستخدم عادي إلى مدير.
- حسابات الإدارة الموجودة في قاعدة قديمة محفوظة كما هي.
- لأول تثبيت فقط، من Terminal الاستضافة داخل مجلد forsah:
  php bootstrap-admin.php
  سيطلب الاسم والبريد وكلمة مرور قوية. الأداة محظورة عبر الويب.
- إذا لم يتوفر Terminal اطلب من دعم الاستضافة تشغيل الأداة عبر CLI.
- واجهة الإدارة: https://t3lam.site/forsah/#/admin

استكشاف المشاكل:
- 503: راجع سجل أخطاء PHP. غالبًا لا يستطيع PHP إنشاء المجلد الخاص؛
  أنشئ forsah-private خارج public_html بالملكية والصلاحيات المناسبة
  لمستخدم PHP أو حدد FORSAH_DB_PATH. لا تستخدم chmod 777.
- 500 بعد الرفع: تأكد أن الاستضافة تسمح بتعليمات .htaccess وأن mod_rewrite
  وmod_setenvif متاحان، وراجع Error Log لدى الاستضافة.
- images_supported=false: فعّل GD في إعدادات PHP.
- 401 رغم تسجيل الدخول: تأكد أن الاستضافة تمرر Authorization إلى PHP.
- Nginx وحده: يحتاج مسؤول الخادم قواعد حماية مكافئة؛ لا يدعم .htaccess.

الواجهة مضبوطة على https://t3lam.site/forsah/api.php. الصور تُخزَّن في قاعدة
البيانات الخاصة وتُقدَّم عبر API بصلاحيات، دون مجلد uploads عام.
الإشعارات مستبعدة حسب الطلب، والبصمة تعمل في APK على جهاز Android مدعوم.
