فرصة — قاعدة البيانات داخل مجلد الخادم
======================================

فك الضغط مباشرة داخل public_html/forsah، دون إنشاء مجلد إضافي.
البنية:
  index.html
  assets/
  api.php
  market.php
  config-loader.php
  hosting-auto.php
  .htaccess
  database/
    .htaccess
    forsah.seed.sqlite
    forsah.sqlite       (يُنشأ تلقائيًا عند أول طلب API)

قاعدة التشغيل المطلوبة ستكون: forsah/database/forsah.sqlite
ملفات WAL/SHM والملح الخاص والقفل تبقى داخل database أيضًا.
قاعدة seed المرفقة فارغة بجميع الجداول وليست قاعدة التشغيل؛ إعادة فك
الحزمة لا تستبدل forsah.sqlite أو بيانات المستخدمين.

التشغيل:
1) خذ نسخة احتياطية قبل الرفع، ثم فك الحزمة داخل مجلد forsah.
2) تأكد من استخراج ملفي .htaccess (في الجذر وفي database).
3) احذف ZIP من الاستضافة بعد الفك.
4) افتح https://t3lam.site/forsah/api.php?resource=health
   المطلوب: ok=true وversion=2 وimages_supported=true.
5) افتح https://t3lam.site/forsah/ لاستخدام التطبيق.

المتطلبات والحماية:
- Apache 2.4 أو LiteSpeed متوافق، مع دعم .htaccess وmod_rewrite وmod_env
  وmod_setenvif والسماح بالتعليمات المرفقة. Nginx وحده لا يشغّل هذه الحزمة
  افتراضيًا؛ يحتاج قواعد حماية مكافئة يضبطها مسؤول الخادم.
- PHP 8.1+ مع pdo_sqlite وmbstring وgd، ومستخدم PHP يستطيع الكتابة في database.
- upload_max_filesize >= 3M وpost_max_size >= 4M، وHTTPS صالح.
- ملف .htaccess الجذري يحظر database وملفات SQLite والنسخ المساعدة، وملف
  database/.htaccess يحظر كل محتويات المجلد.
- الخادم يرفض فتح القاعدة عبر HTTP إن لم تصله علامة الحماية التي يضبطها
  .htaccess. لا تضبط FORSAH_PROTECTED_DATABASE يدويًا لتجاوز هذا الشرط.
- تحقق بنفسك أن الروابط التالية تعيد 403 أو 404، ولا تنزّل أي ملفات:
  https://t3lam.site/forsah/database/forsah.sqlite
  https://t3lam.site/forsah/database/forsah.seed.sqlite
  https://t3lam.site/forsah/database/forsah.sqlite-wal
  https://t3lam.site/forsah/database/ip-salt
- لا تحذف قواعد الحماية ولا تستخدم chmod 777. لا تنشئ مسارًا بديلًا عامًا
  أو alias يمكنه إظهار database. وضع القاعدة خارج الويب أكثر أمانًا بطبيعته؛
  هذا الإصدار يضعها داخل المجلد حسب طلبك ويعتمد على حماية خادم الويب.

نقل بيانات النسخة السابقة (إذا سبق تشغيلها):
- أوقف الكتابة إلى التطبيق مؤقتًا وخذ نسخة SQLite متسقة باستخدام أداة
  النسخ الاحتياطي لـ SQLite، أو بعد إيقاف جميع اتصالات القاعدة وإتمام checkpoint.
  لا تنس WAL؛ نسخ ملف sqlite وحده أثناء وجود عمليات كتابة قد يفقد بيانات.
- انقل النسخة المتسقة من forsah-private/forsah.sqlite إلى
  public_html/forsah/database/forsah.sqlite، مع ملكية وصلاحيات مناسبة لمستخدم PHP.
- إن كان FORSAH_DB_PATH أو FORSAH_CONFIG_PATH مضبوطًا صراحة في بيئة PHP،
  عدّله أو أزله حتى لا يستمر التطبيق باستخدام المسار القديم.
- الحزمة الجديدة لا تحمل الإعداد الخارجي القديم تلقائيًا. عند اكتشاف
  قاعدة خارجية سابقة مع غياب القاعدة المحلية، تتوقف بدل إنشاء قاعدة فارغة
  وإخفاء بياناتك؛ أكمل النقل أعلاه ثم أعد المحاولة.
- لا تستبدل القاعدة الحقيقية بملف seed الفارغ.

حساب الإدارة:
- لا توجد كلمة مرور افتراضية، ولا تُمنح الإدارة لأول مستخدم عادي.
- الحسابات الحالية تبقى في القاعدة المنقولة.
- للتثبيت الجديد فقط، من Terminal داخل مجلد forsah:
  php bootstrap-admin.php
  الأداة تطلب الاسم والبريد وكلمة المرور، وتستخدم القاعدة المحلية نفسها،
  ولا يمكن تشغيلها عبر الويب. بدون Terminal اطلب من دعم الاستضافة تشغيلها.
- الإدارة: https://t3lam.site/forsah/#/admin

إذا ظهر 503 راجع سجل PHP: قد تكون .htaccess غير مفعلة، أو database غير
قابل للكتابة، أو توجد قاعدة قديمة تحتاج نقلًا. إذا ظهر 500 تأكد من سماح
الاستضافة بتعليمات .htaccess وتفعيل الوحدات المذكورة. لا تتجاوز حماية القاعدة
لحل الخطأ. الواجهة تتصل بـ https://t3lam.site/forsah/api.php.
