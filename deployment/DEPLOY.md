# تحديث فرصة إلى الإصدار 2 — رفع يدوي

## قبل الرفع

- PHP 8.1+، `pdo_sqlite` و`mbstring` و`gd`، HTTPS. اضبط `upload_max_filesize=3M` و`post_max_size=4M` وذاكرة PHP لا تقل عن 128M.
- خذ نسخة احتياطية متسقة من SQLite بأداة `sqlite3 ... '.backup ...'` أو أوقف الكتابة أثناء النسخ. لا تنس ملفات WAL عند نسخ الملفات مباشرة. لا تستبدل قاعدة المستخدمين بقاعدة فارغة.
- الجدول الجديد والإضافات تُنشأ تلقائيًا دون إسقاط الجداول القديمة.
- الإعلانات والتذاكر القديمة التي لم تكن مرتبطة بحساب لا تُنسب تلقائيًا لأي بريد جديد: هذا مقصود لمنع الاستيلاء على بيانات الضيوف. تبقى متاحة للإدارة.

## محتويات الحزمة

- `public/`: ارفع **محتوياته** إلى `public_html/forsah/`، بما فيه `.htaccess` على Apache.
- `private/config.example.php`: لا ترفعه داخل `public_html`. انسخه إلى `/home/اسم_حساب_الاستضافة/forsah-private/config.php` وعدّل المسار إلى **قاعدة البيانات الحالية** والسَلط العشوائي. يمكن نقل القاعدة بأمان إلى نفس المجلد الخاص. المجلد 0700 والملف 0600 وبملكية مستخدم PHP.
- `tools/`: أدوات CLI فقط، ضعها خارج جذر الويب. لا تحتاج إنشاء مدير جديد عند وجود مدير حالي.
- إذا كانت بنية الاستضافة مختلفة، اضبط `FORSAH_CONFIG_PATH` في بيئة PHP على المسار المطلق إلى `config.php`. المسار التلقائي هو مستويان فوق مجلد API ثم `forsah-private/config.php`.
- لا ترفع ملف ZIP كاملًا أو `private/` أو `tools/` إلى المسار العام.

Apache: ملف `.htaccess` يحظر الملفات الداخلية ويُمرر Authorization. على Nginx نفّذ قواعد مكافئة: السماح بتنفيذ `api.php` فقط داخل مجلد التطبيق، حظر ملفات القواعد والنسخ الاحتياطية، وتمرير `HTTP_AUTHORIZATION` إلى PHP-FPM. إعدادات Nginx لا تقرأ `.htaccess`.

إن كانت هذه أول قاعدة جديدة فقط:

```sh
FORSAH_CONFIG_PATH=/home/ACCOUNT/forsah-private/config.php php /path/outside/public/tools/bootstrap-admin.php
```

الأداة تطلب كلمة مرور المدير في الطرفية. لا ترسلها في المحادثة ولا تضعها داخل APK.

## التحقق بعد الرفع

افتح `https://t3lam.site/forsah/api.php?resource=health`: يجب ظهور `version: 2` و`images_supported: true` و`ok: true`.

شغّل `npm run check:server` أو أعد تشغيل workflow. الفحص لا يكتب بيانات في الإنتاج. عدم نجاحه يعني أن APK الجديد ليس جاهزًا للاستخدام مع الاستضافة حتى لو نجح بناؤه.

اختبر بحسابين مخصصين للاختبار:
1. التسجيل والدخول والخروج وتغيير كلمة المرور (إبطال الجلسات القديمة).
2. إنشاء إعلان ورفع صورة؛ لا يظهر للعامة وهو pending. من لوحة الإدارة افتح تعديل الإعلان لمراجعة الصور ثم اعتمده.
3. الحساب الثاني يبحث ويحفظ للمفضلة ويرسل رسالة وبلاغًا.
4. تأكد أن صاحب الإعلان يقرأ الرسالة ويرد، وأن الحساب الثالث لا يصل للمحادثة.
5. افتح تذكرة من الحساب، رد من الإدارة، واقرأ الرد وأرسل متابعة من الحساب.
6. جرّب منع الشبكة: يجب ظهور خطأ وعدم إظهار نجاح إرسال وهمي.
7. جرّب APK على جهاز فعلي: اختيار صورة، الرجوع، لوحة المفاتيح، البصمة والتراجع عنها، الخلفية ثم فتح الجلسة، تغيير البصمات المسجلة. البصمة تحتاج Android مع strong biometrics؛ لا توجد محاكاة نجاح على جهاز غير مدعوم.

الإشعارات مستبعدة بناءً على الطلب. المحادثات تستخدم polling كل 3 ثوانٍ أثناء ظهور المحادثة فقط، وليست إشعارات عند إغلاق التطبيق. الدعم يُحدَّث بزر التحديث، ولا يرسل بريدًا تلقائيًا.

## حدود مهمة

- APK موقّع Debug للاختبار، وليس إصدار متجر. قد يتغير مفتاح Debug بين تشغيلات CI؛ عند تعارض التوقيع احذف النسخة السابقة (يحذف ذلك بيانات الجهاز) أو جهّز مفتاح Release ثابتًا قبل التوزيع.
- اللغة الإنجليزية تشمل واجهة المستخدم العامة؛ لوحة الإدارة الحالية بالعربية، ومحتوى المستخدمين لا يُترجم آليًا.
- تسجيل الحساب بالبريد وكلمة المرور لا يثبت ملكية البريد. لا توجد رسائل تحقق أو استعادة بالبريد بدون إعداد خدمة بريد. لا تعتمد عنوان البريد وحده لإثبات الهوية أو نقل بيانات قديمة.
- البصمة تفتح جلسة مشفرة على الجهاز، وليست بديلًا عن صلاحيات الخادم؛ تنتهي جلسة المستخدم بعد 30 يومًا أو عند إبطالها.
- لا يوجد تكامل مدفوعات أو حجز خدمات؛ التطبيق سوق إعلانات وتواصل، ولا يدّعي توفير مزودي خدمات دون إدخالات حقيقية.
